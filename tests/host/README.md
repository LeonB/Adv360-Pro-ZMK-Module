# Host-side tests

Plain C, no Zephyr toolchain needed: `make -C tests/host test`.

| Test | Proves |
|---|---|
| `test_baseline_equiv` | The pure renderer (`src/adv360_status_render.c`) still produces exactly the pixels of the original driver (`ref/proffan_baseline.c`, verbatim from `41d16a2`), except for the deliberate parity changes listed in the test header. |
| `test_fork_differential` | The renderer matches the official firmware's LED code (`ref/fork_underglow.c`, verbatim from `refil/zmk@d93499bb`) tick by tick: every layer, lock combination, BT profile / state, split-link state, and battery level. |

| `test_underglow_differential` | The underglow engine (`src/adv360_underglow_engine.c`) matches the fork's own functions: ~970k random and long-run steps of commands (on/off/toggle/select/cycle/colour/hue/sat/brightness/speed, including invalid arguments) and ticks, comparing return codes, state and pixels. |

| `test_blink_schedule` | The driver may sleep until `adv360_blink_next_edge_ms()`: for every blinking state and every millisecond, the frame is unchanged until that edge and changes at it (where the blink is visible), and steady states never change. |

| `test_underglow_plan` | The driver's pure decisions: when to wake next (`adv360_ug_plan_wake`: nothing / next tick / next blink edge), when the self-test has finished animating, and whether the shared LED state is the boot default. The long runs in `test_underglow_differential` also check that "not animating" really means the frame no longer changes. |

| `test_battery_peek` | `STP_BAT`: starting from the default setup the result equals the fork's select-effect sequence; otherwise the previous effect and on/off state are restored exactly, whatever the order of presses, releases and changes made during the hold. |

`ref/` holds reference oracles. `ref/fork_underglow.c` is generated by `ref/extract_fork_oracle.py`
from the fork's source at a pinned commit; do not edit it, change the generator instead. Only the
stub headers adapt the extracted code to the host. CI runs these tests on every push.

## What these tests do not cover

They test the colour logic only. Event wiring, the blink timer, ext-power handling and the split
sync run on the device and are covered by the firmware build plus the manual hardware checklist.
